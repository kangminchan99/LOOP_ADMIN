# 보안과 권한 경계

이 문서는 `loop_admin`에서 접근할 수 있는 데이터와 실행 가능한 작업의 경계를 정의한다.

## 데이터 분류

| 데이터 | 분류 | 저장 위치 | AI 접근 허용 여부 |
|---|---|---|---|
| 관리자 비밀번호 | 비밀정보 | 서버/인증 시스템 | 허용 안 함 |
| Access Token | 비밀정보 | 브라우저 또는 Cookie | 코드/문서 기록 금지 |
| Refresh Token | 비밀정보 | 가능하면 HttpOnly Cookie | 코드/문서 기록 금지 |
| 유저 이메일/닉네임 | 개인정보 | `loop_server` DB | mock 또는 익명 예시만 허용 |
| 게시글/댓글 내용 | 사용자 생성 데이터 | `loop_server` DB | 실제 운영 데이터 사용 금지 |
| API Base URL | 설정값 | `.env.local` | 예시 URL만 허용 |

## 금지 사항

- 비밀키, 토큰, 비밀번호를 코드나 문서에 기록하지 않는다.
- 실제 개인정보와 운영 데이터를 테스트 데이터로 사용하지 않는다.
- 승인 없이 운영환경에 접근하거나 배포하지 않는다.
- 보안 검사를 통과시키기 위해 검사 규칙을 비활성화하지 않는다.
- 관리자 권한 검사를 프론트 화면 숨김만으로 처리하지 않는다.
- `NEXT_PUBLIC_` 환경변수에 민감정보를 넣지 않는다.

## 승인이 필요한 작업

- 외부 네트워크 접근 및 파일 다운로드
- 새로운 패키지 설치
- 인증, 권한, 토큰 저장 정책 변경
- 운영 API, 운영 로그, 운영 데이터 접근
- 원격 저장소 push, 병합, 릴리스 및 배포
- 데이터 삭제 또는 복구하기 어려운 변경

## 비밀정보 관리

- 로컬 개발용 값은 `.env.local`에 둔다.
- `.env.local`은 Git에 커밋하지 않는다.
- `.env.example`에는 키 이름과 안전한 예시 값만 둔다.
- 관리자 인증 토큰 저장 방식은 구현 전에 별도 결정한다.

권장 방향:

```txt
초기 MVP: accessToken 기반 Bearer 인증
고도화: Next.js Route Handler + HttpOnly Cookie 기반 BFF 구조
```

## 보안 검증

### 게시글 삭제

- 브라우저는 `DELETE /api/admin/posts/:id`를 호출한다. Route Handler는 Origin·양의 안전한 정수 ID·accessToken 쿠키를 검사한 뒤 NestJS `DELETE /admin/posts/:id`로 전달한다.
- 최종 권한은 NestJS의 `JwtAuthGuard + AdminGuard`가 검사한다. 기존 앱의 작성자 전용 `DELETE /posts/:id` 권한은 변경하지 않는다.
- HttpOnly 토큰을 브라우저 JavaScript에 노출하지 않는다. 성공은 본문 없는 204이며 서버 내부 오류 본문은 전달하지 않는다.
- 확인창에서 게시글 ID를 입력해야 삭제할 수 있다. 요청 중 중복 클릭을 차단하고 자동 재시도하지 않는다.
- 물리 삭제이며 댓글의 게시글 FK는 CASCADE로 선언되어 있다. 운영 DB 제약은 별도 확인한다. S3 파일·발송된 알림·과거 통계의 일괄 정리는 이번 범위가 아니다.
- DB 삭제와 Redis 캐시 무효화는 원자적이지 않다. 통신 오류나 캐시 오류가 나도 이미 삭제됐을 수 있어 목록을 다시 확인한다.
- `deleted=1`은 완료 안내용 URL 값이지 삭제 성공이나 권한의 증거가 아니다.
- 삭제 감사 로그와 복구 정책은 후속 과제다. 실제 운영 데이터로 테스트하지 않는다.

### 유저 삭제

- 브라우저는 같은 출처의 `DELETE /api/admin/users/:id`를 호출한다.
- Route Handler는 Origin·양의 정수 ID·인증 쿠키를 확인하고 기존 NestJS `DELETE /users/:id`로 전달한다. 관리자 권한은 기존 서버 Guard가 최종 검증한다.
- Access Token을 클라이언트 컴포넌트에 전달하지 않는다. 서버 오류 본문도 그대로 노출하지 않는다.
- 확인창에서 유저 ID를 직접 입력해야 삭제할 수 있다. 삭제 요청은 자동 재시도하지 않는다.
- 기존 API는 물리 삭제다. 연관 데이터 삭제는 기존 DB 관계 설정을 따르며 게시글·S3 파일의 일괄 삭제를 추가하지 않는다. 기존 API의 관리자 대상/본인 대상 삭제 정책도 바꾸지 않는다.
- 테스트는 모의 응답을 사용한다. 실제 사용자 삭제는 운영자가 확인창에서 직접 수행한다.


기본 검증:

```bash
npm run lint
npm run build
```

추가 권장:

```bash
npm audit
```

`npm audit fix --force`는 breaking change를 만들 수 있으므로 승인 없이 실행하지 않는다.
