# 테스트 및 검증

이 문서는 `loop_admin` 작업 완료를 판정하기 위해 실제로 실행할 수 있는 검증 방법을 기록한다.

## 빠른 검증

### 댓글 삭제 — 검증 계획

[댓글 삭제 체크리스트](ADMIN_COMMENT_DELETE.md#검증-체크리스트--아직-미실행)에 따라 구현 후 검증한다. 현재 댓글 삭제 전용 테스트를 추가하거나 실행하지 않았다. Mock 또는 격리된 테스트 데이터로 권한·Origin·빈 204 응답·통신 실패·중복 클릭·페이지 보정·모바일 접근성을 확인한다. 실제 운영 댓글은 테스트로 삭제하지 않는다.


### 게시글 삭제 검증 범위

기본 구현과 사용자 동작 확인 보고가 있다. 게시글 삭제 전용 자동 테스트는 아직 추가하지 않았다. 유저 삭제 테스트 통과를 게시글 삭제 테스트 통과로 간주하지 않는다.

- 버튼 수정 당시 해당 파일 ESLint와 TypeScript 검사 통과. 이후 테이블·페이지 연결을 포함한 최종 `npm run lint`, `npm run build` 결과는 별도 확인한다.
- 승인된 테스트 게시글로 확인창 열기, ID 불일치 시 비활성, 취소 시 무요청, 중복 클릭 방지, 성공 후 목록·전체 건수 갱신을 확인한다.
- 검색어·limit 유지, 마지막 페이지 마지막 행 삭제 시 이전 유효 페이지 이동, 전체 삭제 시 1페이지 빈 목록을 확인한다.
- 무인증 401, 일반 사용자 403, 잘못된 ID 400, 없는 대상 404와 통신 실패 안내를 확인한다.
- 375px와 데스크톱에서 테이블 가로 스크롤, 확인창 버튼 접근, 키보드 포커스와 Escape 동작을 확인한다.
- 추가할 자동 테스트: Route Handler Origin·쿠키 검사, 204 빈 응답, 오류 전달, API 함수 및 서버 캐시 무효화. 테스트는 모의 응답 또는 격리된 테스트 DB를 사용한다.

### 공통 명령

작은 변경 후 먼저 실행한다.

```bash
npm run lint
```

## 전체 검증

PR 또는 병합 전에 실행한다.

```bash
npm run lint
npm run build
```

## 테스트 종류

| 종류 | 위치 | 실행 명령 | 사용 시점 |
|---|---|---|---|
| 린트 | 전체 TS/TSX | `npm run lint` | 모든 변경 |
| 타입/빌드 검사 | Next.js 전체 앱 | `npm run build` | PR 전 |
| 유저 삭제 Route/API 단위 테스트 | `tests/delete-user.test.mjs` | `npm run test:user-delete` | 유저 삭제 변경 시 |
| E2E 테스트 | 아직 없음 | TODO | 로그인/관리자 플로우 구현 후 |

## 로컬 수동 확인

유저 삭제는 `npm run test:user-delete`로 Origin·ID·인증 쿠키 검증, 서버 권한 거부/404/409, 빈 성공 응답, 통신 실패를 모의 응답으로 검사한다. 실제 계정은 삭제하지 않는다.

수동 확인은 승인된 테스트 계정으로만 수행한다: `/users` 검색 후 삭제 확인창 열기 → ID 입력 전 삭제 비활성 → 취소 시 요청 없음 → 삭제 성공 후 검색 조건/전체 건수 갱신 → 마지막 페이지 마지막 행 삭제 후 이전 페이지 이동. 375px 화면에서는 표의 가로 스크롤과 확인창 버튼 접근성을 확인한다.


개발 서버:

```bash
npm run dev -- -p 3001
```

확인 주소:

```txt
http://localhost:3001
```

확인 항목:

- 관리자 홈이 표시되는가?
- 브라우저 탭 제목이 `Loop Admin`인가?
- 콘솔 에러가 없는가?
- 반응형 레이아웃이 깨지지 않는가? 세부 기준은 `docs/RESPONSIVE_LAYOUT.md`를 따른다.

## 버그 수정 절차

1. 버그를 재현하는 가장 작은 절차를 기록한다.
2. 가능하면 실패하는 테스트 또는 재현 페이지를 만든다.
3. 코드를 수정한다.
4. 가까운 검증부터 실행한다.
5. `npm run lint`와 `npm run build`를 실행한다.

## 테스트 데이터

- 실제 개인정보나 운영 데이터를 테스트 데이터로 사용하지 않는다.
- mock 데이터는 `src/features/*/data` 또는 테스트 전용 위치에 둔다.
- 운영 API 응답 예시는 민감정보를 제거한 형태로만 문서화한다.

## 검증할 수 없는 경우

필요한 환경이나 권한이 없어 검증하지 못한 경우, 통과했다고 가정하지 말고 다음을 보고한다.

- 실행하려던 명령
- 실패하거나 실행하지 못한 이유
- 사람이 확인해야 할 절차
